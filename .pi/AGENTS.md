## Decisions

- 2026-09-03: **Animations are presence-driven, never timer-driven.** Deleted the drawer's `drawerOpen` mirror + `DRAWER_ANIM_MS` unmount timeout + double-`requestAnimationFrame` — a rig whose only jobs were to make a CSS transition actually run and to hold the element mounted while it left — in favour of `<AnimatePresence>` + `motion`. Four rules that cost real debugging time: (1) AnimatePresence re-renders the removed child **with its last props**, so an exiting drawer keeps showing its task even when `selectedTask` went null because the task was deleted — no snapshot ref needed; (2) it must wrap the `createPortal(...)` **call**, since an ancestor cannot see a child living in `document.body`; (3) a measured popover position must **never be cleared on close**, or the exit frame flashes at 0,0; (4) a nested `motion` child with `variants` but no `initial`/`animate` inherits the parent's labels, so a scrim and its card animate off one presence check. Field editors stopped needing effects the same way: title/description seed their draft in the click handler and render `value` when idle; the comment composer's @mention is a `useState` **initializer** + `key={replyTo?.id ?? "root"}` + `autoFocus={replyTo !== null}`; DatePicker stores a `monthOffset` from the value's month instead of an absolute month, so re-anchoring for another task is free.
- 2026-09-03: **`redirect()` during render replaced the two sign-out effects** (AppShell, `/teams/[id]`). Next's client `RedirectErrorBoundary` catches the throw and calls `router.replace`, so the shell never paints for a signed-out user; `/login` is outside AppShell and `proxy.ts` still guards the server side. Two placement constraints that are easy to get wrong: the call must sit **below** every hook (hooks can't be conditional) and **above** the loading branch (or it's unreachable). Behaviour change worth knowing: `push` → `replace`, so Back no longer returns to an expired page.
- 2026-09-03: **Data fetching stays in `useEffect`; only view state moved to Jotai.** Converting the 5 fetch effects to async atoms + `<Suspense>` would rewrite every loading/error UI in the app — the same trade already made in the 2026-08-21 "no TanStack Query" decision. Promoted to atoms instead: filter / sort / collapsed groups (per-user prefs, global rather than per-container). Left local on purpose: the task list, the open drawer and the create-modal fields — one consumer each, no reason to outlive the page.
- 2026-09-03: **Closed the typing holes by naming the types, never by casting them.** `lib/api.ts` exports `TaskPatch` = exactly the backend's `.strict()` `updateTaskSchema` (`description`/`due_date`/`project_id` nullable — NOT `Partial<Task>`, which rejects the nulls), plus `TeamDetail` and `BindingDraft`; `api.updateTask` takes `TaskPatch`, so the drawer's `as Parameters<typeof api.updateTask>[1]` is gone rather than laundered. `req()` reads `JSON.parse` through `unknown` + an `isErrorBody` narrow (spreading the parsed blob into `ApiError` is how a non-conforming body used to leak); its one surviving assertion, `body as T`, is commented as the deliberate trust it is. Analytics' private `cn()` copy (clsx without twMerge) deleted in favour of `lib/cn.ts`.
- 2026-09-03: **Motion stops at the tooltip in the heatmap.** The 365-column track and its `memo`ed `HeatRow` cells are never `motion` nodes (that memo exists so hover costs nothing); drag-scroll keeps writing `scrollLeft` in an effect (motion's `drag` needs measured `dragConstraints` = another effect, and fights native overflow panning); the tooltip animates **opacity only**, because interpolating `left`/`top` toward a moving cursor is how tooltips lag.

- 2026-09-02: **One breadcrumb header app-wide** (owner-driven): big per-page titles removed from teams + analytics; all pages copy the tasks header verbatim. New page = copy the bar (star + size-8 bell included), change only the leaf label.
- 2026-09-02: **PRD-06 container model settled** (see Facts for the summary). Owner explicitly rejected: manual workspace⇄team convert buttons, any parent/link between projects/KPIs/workspaces, and creator-only binding (chose Linear-style: visibility ⇒ bindability). Personal items stay visible to teammates — "private" only exists as a whole workspace. Accepted ⚑ defaults still open to veto at PRD review: in_progress=0.5 fraction, canceled excluded, project optional per task, delete-archives-when-bound.
- 2026-09-02: **One error map + one hook, not per-page try/catch.** Replaced 44 scattered `isApiError(e) ? e.message : "…"` sites with `lib/errors.ts` (code → kind/action/copy) + `hooks/useAsyncError.ts`. Mapping is by CODE, never status alone (the backend answers 403 before checking existence so it never leaks which ids exist). Server copy is shown verbatim only where it's already human (`serverSays`), which also killed the dead `invalid_username`/`weak_password` branches in signup — those codes never existed; they arrive as `invalid_input`. New backend code = new row in `ERROR_RULES`, nothing else.
- 2026-09-02: **Prisma constraint matching goes through `backend/src/lib/db-error.ts`.** With Prisma 7 + the pg driver adapter, `P2002` no longer carries `meta.target` and `error.message` is Prisma's generic rewrite — the index/trigger name only appears in `meta.driverAdapterError.cause.originalMessage`. The old `meta.target.includes(...)` checks therefore silently never matched: duplicate signup and re-inviting returned **500** instead of 409 (both fixed + verified live). `isUniqueViolation(e, "index_name")` / `isTeamFull(e)` flatten code + SQLSTATE + both messages into one haystack.
- 2026-09-02: **PRD-06 built exactly as specced** — no design drift: owner-only team scope, visibility ⇒ bindability, zero linking, one-way workspace→team flip on acceptance. Jotai adoption started here (session/containers/meta); untouched pages keep their `useState`.
- 2026-09-02: Progress card is a **day-cell heatmap, not bars**. Bars snapped to column *edges* while the date numbers sit *centred* in their column, so every bar read half a day off ("the bar is not align to the date"). One box per day inside the day's own grid column removes that whole bug class. Supersedes the 2026-08-21 positioned-div bar Gantt and its "actual bar starts at `in_progress`, planned band from creation" rule — the band is gone, the cells carry it.
- 2026-09-02: **Two different "today"s, knowingly.** Backend `/analytics` buckets by UTC day (`setUTCHours`), so the Activity chart rolls over at 08:00 local; the heatmap uses the browser clock anchored at local midnight. Only diverges between midnight and 08:00 — leave it unless the user asks to unify.
- 2026-09-01: **Tasks have no user-entered start date.** The due-date chip is a single-date picker (`tasks/DatePicker.tsx`, replaces `DateRangePicker.tsx`; one click commits + closes, presets Today / +7 days / No date, accepts both `YYYY-MM-DD` and the API's RFC3339). The real start is observable from the `todo → in_progress` event, so a hand-picked start date was noise. `tasks.start_date` dropped (migration `20260901000000_drop_task_start_date`) plus `start_date` removed from create/PATCH schemas, `TaskResponse`, `api.Task`. Drawer clears with `due_date: null` (was `undefined`, which JSON.stringify dropped → "No date" did nothing).
- 2026-09-01: Analytics window = **trailing 14 days ending today** (`WINDOW_DAYS=14` → `range=14`; right edge = today, `interval={0}` so every date is ticked; missing days carry the previous cumulative forward). Supersedes the calendar-month + Week 1–4 dropdown model: a month window is mostly future carry-forward days, so all four lines drew dead straight. The flatness was the *window*, not the cumulative-lines choice below — that stands.
- 2026-08-21: Analytics chart = **lines-only plotting cumulative running totals** (`type="monotone"`); non-decreasing, quiet days carry forward. Tooltip shows e.g. `Created 47 (+3 today)`, delta computed client-side from the previous day. User rejected raw-count horizontal segments, bar charts, AND a 7-day rolling average (redundant once cumulative is naturally smooth).
- 2026-08-21: `recharts@^3.10.1` pin (React 19; no chart lib in the global stack — becomes project pin). Token `--color-created: #0ea5e9` (+soft); other series reuse status colors.
- 2026-08-21: Realtime = **SSE** (`streamSSE`) + Redis pub/sub (`ioredis`), NOT WebSocket (one-way push; plain HTTP keeps cookie auth/CORS; `EventSource` auto-reconnect). One `GET /api/events` channel, `{topic,event,data}` envelope, `user:<id>` reserved for notifications (PRD-05).
- 2026-08-21: Comments = REST CRUD + optimistic UI (temp-id insert, rollback); SSE phase 3 adds live updates; REST stays source of truth. No TanStack Query.

- 2026-08-18: Go+Gin → Hono+TS (shared stack; JSON/cookie unchanged). Skipped `ioredis` until a caching/pub-sub use case. Root `dev` = `pnpm -r --parallel`. `cn()` = clsx+twMerge. Priority cycle low→medium→high. Flag = attention toggle.

## Conventions

- snake_case responses via `lib/types.ts` mappers (`toUser/toTeam/toTask/toInvitation/toComment/toAnalytics`).
- PRD-03 endpoints wrap `{ comments }`/`{ comment }`; older task/team endpoints return bare — don't "fix" either.
- `routes/comments.ts`: list/create `/tasks/:id/comments`, edit/delete `/comments/:id`; membership + author-only. Replies flatten to root.
- `routes/analytics.ts`: membership-gated; server buckets + cumulative running totals over full history (window edges accurate; series ends today). `range` = any integer 1–92 (clamped), default 30. Also hosts `GET /teams/:id/progress` (heatmap data).
- Workspace import: backend deep path `@mokara/db/prisma/generated/client`.
- Cookie `Secure` only in prod; SameSite=Lax.
- Dropdowns: `grid-cols-[1fr_18px]` checkmark slot; selection = checkmark only; hover tint `rgba(99,102,241,0.06)`.
- Toggle row actions: no `transition-opacity`/`focus-within` on inactive branch (decisive).
- State = **Jotai atoms** for shared/global state (module-level atoms, default store, no `<Provider>`); `useState` only for ephemeral local UI. jotai `^2.20.3` is installed (PRD-06 shipped). Shared *state* goes to atoms; shared *constants* (easing, durations, status lists) go in one module, not per file.
- **Motion = `lib/motion.ts` variants only.** A new animated surface gets a new variant there, never an inline easing/duration. Portal popovers: `AnimatePresence` wraps the `createPortal` call and the measured position is never cleared on close. Lists use `layout="position"` only — no size projection through an `overflow-hidden` clip. `ChipShell`'s width-stability ghost (`MinWidthChip`) and the heatmap cells are off-limits to motion.
- **Shared hooks return a memoised object** (`useSession`, `useContainers`, `useContainerMeta`) — listing them in a consumer's `useCallback` deps is legitimate, and a fresh object every render turns that into a refetch loop.
- Session pattern: /me probe once per app lifetime (`booted` guard) + `setSessionUser(user)` called by login/signup — never re-probe per page mount.

## Things NOT to do again

- **HARD RULE — never build or run anything locally that CI is responsible for.** No `docker build`, no `docker run` of app images, no `pnpm build`/`next build`/`start`/`preview` unless a *gate* requires it, no spinning up Postgres/Redis, no background servers "just to check". The owner publishes a release tag and CI builds the images — that is the deliberate feedback loop, so a problem surfaces as a red run we can read and fix. Doing it locally wastes the owner's time and proves nothing CI won't prove better. Allowed locally, and only these: the exit-once gates (`pnpm typecheck` · `lint` · `format` · `db:generate` · `db:migrate:deploy` against the running dev Postgres the owner started), reading files, and git state. A one-shot, self-terminating check is still a build — ask first. (Set 2026-09-03 after a docker build + a throwaway server script were run against the owner's explicit "don't build locally".)
- **When the owner points at a reference repo, the reference IS the spec.** `jejak-athlete` is the CD reference (see Facts). Match its Dockerfiles/workflows step-for-step before reaching for a cleverer design; where mokara must differ, write the delta in PRD-07 §7 with the reason. Deltas added "because it's better" are how drift starts — the `--prod --filter` install I invented broke pnpm's TTY-less modules purge, which the reference's plain install never hits.
- **Don't run dev servers.** User starts their own; verify via typecheck/lint/format/migrate/seed. EADDRINUSE = leftover — `lsof -i :4200,4201`.
- **Date math — never derive a day index from a live timestamp or a `.toISOString()` round-trip.** `Math.round((now - jan1)/DAY)` with `now` = current instant rounds PAST LOCAL NOON up to *tomorrow* (drew the heatmap's today line on the wrong date), and `.toISOString()` shifts back a day in +UTC timezones (duplicate React keys, misaligned axis). Anchor on local midnight: `new Date(y, m, d)`.
- **Don't put HTML into a quoted data attribute in a hand-built string** — the mockup's tooltip leaked `Sat, Aug 15 — In progress` as visible text all over the cells. React escapes props correctly; plain template strings don't. Store plain `data-` values and compose the markup at render time.
- **No bars in the progress card; no bar charts / raw-count segments / rolling averages in the Activity chart.** Day cells for progress, cumulative running-total lines for activity — the user rejected each alternative explicitly.
- **NEVER add behavior I wasn't asked for — especially hiding things.** Root rule behind the analytics week-filter incident: I hid "future" weeks from a dropdown and swapped the chart for a "No activity in this window yet" empty state, both unrequested. User: "don't overcomplicate, don't overthink, just do what I asked; if I didn't ask, don't." Concretely: never filter dropdown options by "not started/empty", never replace a chart/list with an empty-state message, never invent conditional visibility. Render everything (zero-filled if no data). Any such "smart" default must be explicitly asked for first.
- **Do EXACTLY what the user wants, in the phase they want it.** A user-requested feature belongs in the CURRENT phase — only defer what the USER deferred (e.g. KPI strip → later). Don't re-confirm scope repeatedly; once confirmed, execute.
- **Don't over-engineer "simple" requests.** Start with the simple path (`transition-colors`, bg change).
- **No Tailwind pseudo-element slide-ins** (`before:content-['']` unreliable in v4). `background-size` arbitrary prefix is `size:` not `length:`.
- **Don't assume token contrast** — check CSS var values (`--color-surface-2` invisible on white).
- **Don't jump to conclusions on UI feedback** — read screenshots, ask which concern.
- **No speculative adjacent changes** — one targeted fix per request.
- **`absolute left-0 right-0` popovers need a `relative` immediate wrapper** — otherwise they size against the nearest positioned ancestor (the sticky sidebar, padding included) and render wider than their trigger. ContainerSwitcher bug, 2026-09-02.
- **Don't push** to any branch — ASK tier, wait for user.
- **Commits: one per feature, staged by path — `git add .` is a fallback, not the default.** Stage the exact files (`git add packages/x/...`) so each commit is reviewable and bisectable. Reach for `git add .` only when the changes truly cannot be separated, and say so.
- **Commit messages: plain `git commit -m` flags only, kept short.** No heredocs, no `-F <file>`, no multi-line shell-quoted prose. The permission gate pattern-matches the whole command line, so a trigger word inside a message body — `shutdown`, `exec`, `kill` — blocks the commit as a "system power command" and the message reads as if git itself failed (2026-09-03: one commit died three times on the word `shutdown` in its own body). If a long body is genuinely needed, write it to a temp file with the write tool and `git commit -F <path>` — the command line then contains only a safe file path. Never reach for `-c core.hooksPath=/dev/null`, `--no-verify` or force flags to get past a block: the staging or the message is wrong, so fix that instead of routing around the gate.
- **No `useEffect` unless it syncs with something outside React** (timers, listeners, DOM measurement, one-time bootstrap probe). Not for derived state (useMemo / compute in render), not to mirror props into state, not as change-detection chains. Owner rule, 2026-09-02. Corollary for animation, 2026-09-03: **no `setTimeout`/`requestAnimationFrame` rigs to fake mount and exit** — `<AnimatePresence>` owns unmount timing. Every surviving effect carries a comment saying what it syncs, and `react-hooks/exhaustive-deps` is an error, so "delete the dep" is not an available answer.
- **No `as any`, and no cast where a type will do.** `no-explicit-any` is an ESLint error and `packages/frontend` had zero violations — the fix for a type mismatch is to *name* the real type (`TaskPatch`, `TeamDetail`, `BindingDraft`), narrow with `instanceof` (`e.target instanceof Node/HTMLElement` replaced three `as HTMLElement`s), or derive a constant (`STATUS_IDS` from `GROUPS` replaced four `as TaskStatus[]` literals). Superseded: the old note that `as Parameters<typeof api.updateTask>[1]` was an accepted pattern — that cast is gone. Zero `any` / `@ts-ignore` / `@ts-expect-error` / non-null assertions as of 2026-09-03; the only casts left are `body as T` in `req()` and recharts' `payload[0].payload`, both commented.
- **No `h-screen` inside padded containers** — use `h-[calc(100dvh-Xrem)]`.
- **Don't start building before the owner says go** — I installed jotai + rewrote session.ts when the owner only wanted the rules recorded in PRD-06; had to revert both. Rules/decisions land in the PRD + memory first.
- **No `box-shadow`+`border-radius` on a child of `overflow-hidden`** — put the look on the wrapper.
- **Grid/flex children default to `min-width: auto`** — wide content (e.g. the 365-day heatmap track) stretches the whole page instead of scrolling inside `overflow-x-auto`. Add `min-w-0` to the grid/flex item (`AppShell <main>` has it for this reason).
